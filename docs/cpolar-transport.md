# cpolar 电脑侧传输兼容辅助工具

这是国内 IPv4 备用入口的实验性电脑侧工具，不代表所有网络、Android 版本或 cpolar 节点均已通过验收。Android App 仍使用原有扫码、配对和 WebView 工作区。

## 为什么需要单独验证传输

实测出现过入口可达、配对成功和后台只读 RPC 成功，但手机仍停留在加载页的情况。同一脚本采用普通传输时很快完成，采用压缩传输时曾只收到 gzip 文件头；较大的响应也出现过排队和超时。不能仅凭 HTTP 200、WebSocket 握手成功或出现原生桥接对象宣布可用。

`tools/cpolar-http-compat.mjs` 放在 cpolar 与电脑本地 DSH 之间。它保留原始 Host、Origin、Cookie、认证状态码和安全响应头，由 DSH 原有的 `remote-web-ui.config.trustedHosts` 接受真实入口域名。它不会伪装成其他已授权域名。

HTML 在客户端允许时采用带明确 Content-Length 的 gzip；JSON 和小静态响应采用 identity 编码及明确长度。较大静态资源可压缩，压缩结果不足 64 KiB 时回退到 identity。响应连接明确结束。这个策略来自现场对照，用来减少压缩兼容问题和免费线路的带宽压力，尚不能证明中继内部故障的具体实现原因。

## 本地运行与测试

需要 Node.js。配置文件仅保存当前入口和本地 DSH 端口，不包含配对凭据：

```json
{"origin":"https://<allocated-host>.cpolar.cn","targetPort":12345}
```

```powershell
node tools/cpolar-http-compat.mjs "<private-state-file>" 18771
node tools/test-http-compat.mjs
```

将 cpolar 的本地目标指向 `127.0.0.1:18771`。网关只监听回环地址；监听端口和 DSH 端口必须不同。`targetPort` 必须由电脑侧从当前运行的 DSH 验证取得，不能照抄例子。域名支持 `.cpolar.cn` 和 `.cpolar.top`，Host 必须与状态文件的 HTTPS 源一致，允许等价的默认端口 :443。

测试覆盖压缩与 identity 正文完整性、内容长度、协商缓存、Cookie/CSP 保留、认证拒绝、管理接口拒绝、缓冲上限、SSE 和 WebSocket。默认最多缓冲 32 MiB，超限回退流式转发。SSE、范围响应和 WebSocket 不缓存、不压缩、不缓冲整段流。

本地 `GET /__compat_health` 可查看最近请求的路径类别、状态和耗时，不记录查询参数、Cookie、请求体或响应正文。该端点不是工作区业务验收：仍需手机实际显示工作区、实时通道和只读响应。

## 部署边界

账号、Authtoken 的加密存储、客户端启动、真实域名注册和登录后自动恢复属于电脑侧部署。私有凭据、运行状态、日志和配对链接不进入仓库。本工具不自动注册账号，不提供免费固定域名，也不会把已有 Cookie 迁移到另一个域名。

现场监督器应做到单实例运行、只回收可核实归属的子进程、延迟重试、原子更新自己维护的 trustedHosts 条目，并保留其他配置。公网拥堵时不能频繁重启通道；健康探测成功也不能替代业务验收。

免费版地址存在变化限制，需要把变址后的发现和重新配对纳入产品流程；不能向用户承诺永久免重新扫码。区域和地址规则以 [cpolar 官方文档](https://www.cpolar.com/docs) 为准。

## 2026-10-31 验收结果

cpolar 备用链路未通过手机稳定性验收。曾成功显示工作区并取得真实只读响应，但随后冷启动再次长时间等待。已配对 HTML 的本地网关响应约 9 ms，公网 HTTP/1.1 和 HTTP/2 对照仍出现超时或连接重置。大陆 cn 和 cn_top 均有复现。测试通道及自动启动已停用，保留加密配置和诊断材料，不替换原主通道。

两份插件脚本的 identity 正文分别约 11.5 MB、9.2 MB；原 8 MiB 缓冲上限不足，已调为 32 MiB。修正了 HTTPS 默认端口等价判断，增加响应字节数和流式回退诊断。这些是可验证的工具修正，不能据此宣称中继稳定性已解决。

原主通道 Android 16 真机复核可进入工作区、建立实时连接、取得只读响应；正常包覆盖安装后仍可进入已有对话，顶部加载提示修复已确认。后续原主通道也观察到真实 HTTP 503 和部分业务失败，不能称为全程稳定。当前主入口由 Relay 提供，状态接口同时报告另一条 tunnel 为 running，应分别诊断；不能把所有故障都归入 Cloudflare。不代表 Android 17 原报告设备或其他网络已经通过验收。
