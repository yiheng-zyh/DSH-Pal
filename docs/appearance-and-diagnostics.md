# 显示、缓存与诊断

## 手机、横屏与平板

设置 → 外观 → 网页布局：

- **自动适配**：可用窗口短边小于 600 dp 时采用手机布局；达到 600 dp 时采用至少 1024 CSS px 的大屏视口，随窗口宽度增长。窗口变化后重新判断；真实系统分屏仍需按设备验证。
- **手机布局**：保留手机触控、侧栏与键盘适配。
- **桌面布局**：使用 1280 CSS px 的宽视口，让 DSH 自身展示桌面多栏布局；支持双指缩放。这是显示选项，不是另一套连接方式。

布局选择保存在本机。切换不删除 Cookie、不签发新配对、不改电脑端监听、插件或主题。旋转沿用原 WebView；原生启动页横屏采用左右两区，设置与许可正文限制宽度并可滚动。

设置 → 外观 → 本地色调覆盖启动、顶部栏、设置、原生确认框及网页主题。默认“跟随 DSH 背景”保留 DSH 自己的主题和背景，不依赖指定壁纸插件，也不读取电脑桌面壁纸。本地色调不写回被控端。

## 缓存与加载

设置中按用途进入二级页面，每项清理都有确认：

| 选项 | 范围 | 保留或影响 |
| --- | --- | --- |
| 网页资源缓存 | App 静态资源缓存及 WebView 网络缓存 | 保留 Cookie、站点存储和原生账号；下次需下载资源 |
| 页面本地存储 | 当前地址的 localStorage / sessionStorage | 保留 Cookie；草稿、插件设置乃至存在本地的网页授权可能被移除 |
| 所有网页 Cookie | 当前 WebView 数据环境下所有站点 Cookie | 其他站点存储保留，因此不等于完整退出所有网页授权 |
| 当前站点登录数据 | WebView 按主域清理 Cookie、站点存储和网络缓存，包含子域 | 可能影响同主域的多个入口；保留其他主域登录和原生连接记录 |
| 全部登录与站点数据 | 所有站点 Cookie、站点存储、Service Worker、网页缓存及 App 静态资源缓存 | 网页可能需要重新配对；原生 Tailscale 账号、WireGuard 配置和连接地址保留 |

完整站点清理依赖 WebView 的 DELETE_BROWSING_DATA 能力；不支持时禁用对应按钮并提示更新 WebView，不采用只清部分数据却声称完成的替代办法。

缓存清理只处理 App 自有缓存文件，正在进行的旧下载不会在清理后重新写回。重新加载会走已有草稿/传输保护提示。不要把更新资源和清除登录混为一谈。

## 通知与日志

“通知与后台”下分为通知选项、通知能力检测、通知演示。小米媒体岛仍使用 MediaStyle / MediaSession，效果由系统决定；不改用私有焦点通知协议。

“支持与诊断 → 日志记录”提供总开关和六类开关，默认全部开启：

- 连接与配对：配对、VPN 授权、连接切换。
- 网络与请求：断网、超时、业务请求失败。
- 页面与资源：页面加载、缓存、插件资源。
- 网页交互：脚本、输入、文件、通知回复。
- 通知与任务：系统通知、媒体岛、任务状态。
- 应用与异常：启动、后台生命周期、崩溃。

关闭开关停止该类新增记录，已有日志仍保留。内存保留最近 400 条，每条最多 2048 字符；本次和上次运行文件各最多 128 KiB，以 UTF-8 字节限制循环覆盖。导出覆盖同一个文件、最多 512 KiB，并保留环境信息和问题填写模板。导出前仍应检查内容，避免在公开 Issue 中包含私人信息。

“关于”可离线阅读应用和第三方许可，包含角色、MiSans 与内嵌组件署名。项目 GitHub、Issue、哔哩哔哩地址未确定前显示待配置，不导向示例或虚构网址。


## 横屏与可选插件的适配规则

- 手机横屏采用两行标题区，工具与标签各有位置；可横向滚动的插件工具不会制造额外网格行。原生网络状态移入标题列，减少纵向占位。
- 多个 viewport 标签保持一致，避免网页后加入的标签覆盖本机布局选择。保留原标签节点，不删除框架拥有的 DOM。
- DSH 远控手机适配器若提供 `__dshRemoteAdapt.setEnabled`，桌面布局通过该接口关闭手机适配，切回手机时重新启用。后续网页恢复自身偏好也不能覆盖 App 的桌面选择；缺少接口时保留通用视口适配，不假定安装了特定插件。
- 识别到工作区树时，左栏将工作区放在插件入口之前，外层可滚动，内部会话列表保留独立滚动；内部到边界后可继续滚动外层。没有工作区插件时不保留空白区域，移除插件后会清理适配标记。
- 窄大屏右栏只有在插件声明 `data-sidebar-right-open` 状态时才采用覆盖布局；收起后不留下透明区域拦截输入。未知插件继续沿用原布局，不强行塞入同一种右栏结构。

回归检查可运行 `node tools/test-web-viewport.mjs`。`tools/plugin-layout-fixture.js` 是浏览器隔离 iframe 检查函数，需要传入实际的 plugin-compat.js 与 mobile-layout.css 内容；它验证缺失、移除、未知插件及退出适配的场景，不卸载实际插件，也不证明所有第三方插件均已验证。
