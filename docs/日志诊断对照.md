## 附录：注入脚本的 WebView 兼容性

新增/改动的注入脚本只用了 WebView 早就支持的写法，**没有抬高最低版本要求**：

| 脚本 | 用到的语法 | 最低 Chromium |
|---|---|---|
| `assets/dsh-js-errors.js` | `var` / `function` / `try-catch` / `addEventListener` / `JSON.stringify` / `URL` 构造函数 | 33（WebView 4.4），远低于本 App 已在下限 |
| `PageProbeScript.domSnapshot()` | 同上 + `document.querySelector` / `getBoundingClientRect` / `Array.prototype.slice` | 33 |
| `PageProbeScript.injectCheck()` | 同上 | 33 |
| `PageProbeScript.resourceProbe()` | `performance.getEntriesByType('resource')` | 45（WebView 5.0） |

**明确没用**：`??=`、`||=`、`Array.prototype.at`、`structuredClone`、顶层 `await`、可选链赋值。所以案例 B 的 WebView 126 与案例 A 的 153 都在安全范围内。

已知下限参考：工程里唯一被验证过「跑不动」的是 MuMu 模拟器内置 WebView 110（页面本身起不来，与本次注入无关）。document-start 主注入串里已存在的 `class` / `async-await` 语法本身要求 Chromium 55+，本次改动没有比它更激进。

**降级行为**：任一注入脚本缺失或抛错时，原生侧记 `Inject: missing <name>` 或 `Inject: <script> failed <ErrorName>`，页面功能不受影响（所有注入点都包了 `try/catch`，失败静默）。
