# 真机开发与迭代

## 两种构建

- 默认 `assembleRelease`：公网正式版，关闭 WebView 调试和样式热更新。
- `-PdshUsbDevelopment=true :app:assembleRelease`：USB 开发版，使用同一应用 ID 和签名覆盖安装，保留通知授权和应用数据。
- 开发与正式连接地址、待配对链接和首次配对状态分别保存；切回正式构建恢复公网配置。

## USB 真机工作流

电脑安装 Android SDK、JDK 21 和 Node.js，手机授权 USB 调试后：

```powershell
./tools/start-usb-development.ps1 -Serial '<adb-device-serial>'
```

脚本查找本机现有 DSH 端口、构建开发 APK、覆盖安装、配置 `adb reverse` 并投递配对。
端口探测失败时传入 `-LocalPort <current-dsh-port>`。
之后只需重连数据线或恢复配对，可加 `-AttachOnly` 跳过构建和安装。

链路为手机 `dsh-usb.localhost:18765` → 数据线 → 电脑 `127.0.0.1:18766` 调试代理 → DSH 已有回环服务。
代理只监听 `127.0.0.1`，保留远控配对认证，转发 HTTP 与 WebSocket，不改 DSH 的绑定和 LAN 配置。
使用 `.localhost` 开发别名是为了避免远控插件把数字回环地址误识别为桌面本机，从而绕过远控传输路径。

开发 APK 显示“USB 调试”，页面请求绕过 App 的静态缓存以读取最新文件。
保存 `app/src/main/assets/mobile-layout.css` 后，前台手机页面约 1.2 秒自动更新样式；不刷新对话。
Kotlin 或 JS 注入逻辑变化需要重新构建覆盖安装。插拔数据线后使用 `-AttachOnly` 恢复映射。

```powershell
./tools/start-usb-development.ps1 -Serial '<adb-device-serial>' -AttachOnly
./tools/start-usb-development.ps1 -Serial '<adb-device-serial>' -AttachOnly -Inspect
./tools/start-usb-development.ps1 -Serial '<adb-device-serial>' -Stop
```

停止脚本只停止经完整脚本路径核验的开发代理，并移除其反向端口，不停止 DSH。
`-Inspect` 同时把当前 WebView 检查端点转发到电脑回环端口 9228，供 Chromium DevTools 或 CDP 工具检查布局。
正式包使用不带开发属性的构建命令；正式构建不包含可用的 USB 调试开关。

## 验证与 Git 历史

- 每个可复查的功能或修复独立提交，提交正文记录原因、改变和已验证范围。
- 大改前保留检查点；使用分支和增量提交保存历史，不用强制重置覆盖用户工作。
- 源码、测试和便携脚本进入 Git；真机截图、设备标识、配对凭据及私人配置备份保留在仓库外。
- 静态缓存规则见 `static-resource-cache.md`。运行日志采集使用 `tools/collect-device-diagnostics.ps1`。
- 开源前复查素材许可和署名、依赖许可、个人信息及历史提交；本地开发检查点不等同于发布包验收。

## 键盘、侧栏与设置的后续迭代

- 主窗口使用 `adjustNothing`，原生 IME Insets 只在动画起止发送目标高度；WebView 不再逐帧缩高。输入栏使用合成动画，对话滚动范围只调整一次。
- 键盘偏移变量只写到弹出菜单，不写到页面根节点，避免长对话中数千个节点的继承样式失效。页面尺寸未改变时过滤键盘造成的重复 resize；真实尺寸、缩放和横竖屏变化继续交给网页处理。
- 页面可用时先聚焦 WebView 表面，不主动聚焦编辑器或打开键盘，避免首次输入同时触发壁纸插件的窗口聚焦初始化。
- 右侧栏由一个控制器移动完整的不透明页面，关闭动画完成后才交回原有关闭操作；移除另一套竞争的 CSS 入场动画。对话/轨迹使用连续的选中指示条和内容过渡。
- 原“诊断”入口调整为“设置”，分为连接与页面、通知与后台、缓存与加载、支持与诊断。日志及能力检测留在支持页面；解除配对有二次确认。

### 性能证据的采集范围

`DshRun/Keyboard` 记录原生目标高度与动画时长，`DshRun/Motion` 每次键盘动画输出一条 800 毫秒采样汇总：帧数、最大帧间隔、超过 34 毫秒的帧数、页面高度是否变化。没有逐键日志，也不记录输入内容。
`collect-device-diagnostics.ps1` 同时收集这两类日志、应用帧统计和可选的本机连接状态。USB 开发版可通过 CDP tracing 区分网页脚本、样式重算和绘制耗时。

2026-10-26 本轮最终 USB 包真机连续三次唤起采样：最大帧间隔 50 / 33 / 33 毫秒，超过 34 毫秒的帧数 1 / 0 / 0；页面高度始终不变。输入栏下沿与键盘上沿保持对齐。初始化键盘与立即输入候选词叠加时另有一次 158 毫秒样本，不计作无长帧通过。采集器将最近 20 次键盘过渡中超过 100 毫秒或页面高度变化的记录列入 `performanceSpikes`；日志窗口可能因系统缓冲区回收而缩短。

性能记录必须区分启动阶段、首次输入与重复唤起，不能用一次热态采样代表所有场景。网页初次挂载、长对话切换和插件回调仍可能产生长任务；真机日志与截图保留在仓库外，避免把对话、设备标识和配对信息带入公开源码。

### 右侧栏闪回复验

用户反馈上一版更严重后，改用 CDP screencast 检查真机实际合成帧，复现了半透明内容先覆盖对话、随后外层再次滑入的问题。原有 DOM 背景色、透明度和外层位移检查没有覆盖这个问题，不能再作为无闪回的通过依据。

实际动画列表发现 DockKit 的 `[data-dockkit-host="dock"]` 仍运行桌面 transform 过渡，与外层页面滑动叠加。手机样式关闭该内层位移过渡，并为右栏设置 layout/paint containment，让不透明背景与内容一起裁剪、移动；桌面端不变。

覆盖安装后重新捕获 178 帧，抽查打开、展开中、关闭中及关闭后画面，不再出现此前的透明内容叠加。另测三轮展开中立即连续关闭：最终均隐藏、无残留动画、无横向溢出。上下文页显示正常。这些结果针对已复现的双重位移和绘制重叠，不代表所有第三方插件页面均已完成性能验收。
