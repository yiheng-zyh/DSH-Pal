# 手机静态资源缓存

缓存位于应用私有 `cacheDir/web-static-v1`，总上限 96 MiB、单文件上限 12 MiB。
此目录只属于本功能；淘汰只匹配本功能生成的 SHA-256 文件名，不遍历或删除其他目录。
首次加载仍需下载资源。系统清除缓存后可自动重建，不影响配对数据。

## 更新规则

- 仅拦截当前连接同源的 GET 静态文件（JS/CSS/字体/图片）。
- 排除页面导航、HTML、API、配对、文件下载、附件、实时通道、Range 请求，以及含非版本查询参数的 URL。
- URL 和请求上下文共同生成缓存键，连接源、认证或请求表示变化时隔离。磁盘只保存键的摘要，不能记录请求凭据。
- 内容指纹文件在有效期内直接读取；使用服务端 `max-age`，无明确有效期时指纹资源默认 30 天。
- 固定名称文件每次页面导航检查更新，优先发送 ETag / Last-Modified 条件请求。304 复用原文件；200 完整下载新文件后原子替换。
- 尊重响应及请求的 `no-store`；`no-cache` 要求重新校验。入口页面和插件清单由原页面网络逻辑获取，避免固定清单过期。
- MIME 不符、跳转、认证失败、超限或网络失败交还 WebView。网络故障不以过期代码兜底。
- 文件带内容摘要，损坏时重新下载；写入中断产生的旧元数据与新正文不一致时也会重新下载。
- 正在显示的页面不会被后台强制刷新。新指纹由最新页面引用；固定名称资源在下次加载时检查更新。

## 刷新与诊断

主页面顶部和诊断页均可重新加载当前页面，保留配对和已有资源缓存。
检测到可见输入框中有草稿时先提示；刷新不自动重新发送消息或任务。

诊断页展示本次运行的直接命中、304 校验复用、下载次数及复用资源正文体积。
正文体积不等于压缩后的实际网络流量。`Cache` 日志只记录资源键摘要、字节数和结果，不记录完整网址、Cookie 或认证头。
`tools/collect-device-diagnostics.ps1` 同时采集缓存日志。

测试覆盖：跨实例复用、固定名称资源更新、304、请求/响应 no-store、过期、文件损坏、认证隔离、错误回退、容量淘汰、指纹更新及请求边界。
