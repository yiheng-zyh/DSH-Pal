> **这份是给你看的，不是给 AI 看的。**

## 二、配置前：确认三件前置

没有这三样，后面全都配不了。

- [ ] **电脑装了 DSH 并能打开工作区**
      怎么确认：双击 DSH 桌面端，能看到工作区列表
      没有：打开 <https://github.com/deepseek-ai/deepseek-harness> → 右侧 **Releases**
      → 下载 Windows 安装包 → 装完用你的账号登录

- [ ] **电脑装了 Node.js 22 或更新版本**
      怎么确认：打开 PowerShell，输入 `node --version`，显示 `v22.x.x` 或更高
      没有：打开 <https://nodejs.org/> → 点 **LTS** 那个绿色按钮下载 → 装完**重开一个** PowerShell 窗口
      （不重开会一直提示找不到 node）

- [ ] **知道你的 DSH 是哪个 profile**
      怎么确认：平时双击桌面图标开的 → `desktop`；用命令行 `dsh web` 开的 → `web`
      不确定：告诉 AI「我平时怎么打开 DSH 的」，让它判断

## 三、配置中：按这个顺序做（顺序不能反）

**为什么必须先公网后局域网**：局域网最容易配成功，先把容易的弄完，你会以为完事了，
一出门发现用不了。所以先啃难的那块。

### 第一阶段：公网（决定「出门能不能用」）

- [ ] **配好一条公网通道**
      国内推荐顺序：Sakura Frp（最稳）→ IPv6 直连（有公网 v6 时）→ Cloudflare / Relay（备选）

      **这一步 AI 能做完，但 Sakura 的注册和实名要你来：**
      · 打开 <https://www.natfrp.com/> 注册账号（邮箱即可）
      · 按 <https://doc.natfrp.com/faq/realname.html> 完成实名（要身份证 + 手机验证）
      · 实名通过后，在「隧道」页能拿到**访问密钥** —— 复制它给 AI，
        或让 AI 弹个窗口你自己粘（推荐后者，密钥不进聊天记录）

- [ ] **★ 关键验证：手机关掉 Wi-Fi，只用移动数据，能进工作区并收到回复**
      这一步必须做，不能跳。只看电脑上「配置对了」不算数。
      做不了/做不到 → 告诉 AI，让它继续排查，**不要直接进第二阶段**

### 第二阶段：局域网（决定「在家快不快」）

- [ ] **公网上面的验证过了之后**，再配 Wi-Fi 直连
      为什么：局域网只在家有用，但它能让加载快很多、少耗隧道流量

- [ ] **验证**：手机连家里 Wi-Fi，能进工作区；再切到移动数据，也还能进

### 可选项（看你需不需要）

- [ ] **USB 数据线通道** —— 只有开发调试才需要，日常用不上
- [ ] **公网通道切换插件** —— 只有你配了**两条以上**公网通道才有意义（装了能在 DSH 网页里一键切）
      ⚠️ **装之前必须先装依赖**，否则插件加载失败、DSH 设置里什么都不会出现：
      在 PowerShell 里执行（把路径换成你的）：
      ```powershell
      cd <项目目录>\tools\remote-access
      npm ci --ignore-scripts --no-audit --no-fund
      ```
      成功标志：最后显示 `added 30 packages` 左右。
      为什么容易漏：代码本身是完整的，缺的是它用到的一个包（`yaml`）——
      那个包不在 git 里（`node_modules` 被排除），要自己装。
      **不装会怎样**：DSH 重启后设置里没有「公网通道」区块，日志里只有一句
      看不懂的 `Cannot find package 'yaml'`。

- [ ] **Tailscale 自动配对** —— 只有你用 Tailscale 通道才有意义（装了以后登录完不用再扫码）
      ✅ 这个插件**不需要装依赖**（只用 Node 内置模块），改完配置重启 DSH 就行

## 四、配完之后：逐条核对这张表

把这张表给 AI 看，问它「这些都对上了吗」。**哪条它说不清，就是没做完。**

### 电脑端

- [ ] DSH 正在运行，能打开工作区
- [ ] 远程访问插件已启用（DSH 设置里能看到「远程访问」面板）
- [ ] **插件已「固化到本地」**（这条关系到你以后还能不能重装，见下方专门说明）
      怎么查：PowerShell 里跑
      `Select-String "$env:USERPROFILE\.dsh\profiles\desktop\package.json" -Pattern 'dsh-remote-web-ui'`
      期望：看到的值以 `file:` 开头，形如 `"file:C:/Users/<你>/.dsh/vendor/dsh-remote-web-ui"`
      **如果看到的是 `"0.4.14"` 这种纯版本号 → 还没固化，让 AI 跑 `node tools/vendor-plugin.mjs`**
- [ ] 至少一条公网通道能用，且**手机上关 Wi-Fi 用流量验证过**
- [ ] 局域网直连配好了（除非你明确说了不要）
- [ ] `dsh-mobile` 的 `webserver` 配置仍是 `127.0.0.1` + 端口 `0`（**这项不能改**）
- [ ] 电脑的 DSH 端口不是猜的，是实际查出来的
- [ ] **网关已设成开机自启**，且任务的动作是 wscript.exe（不是 powershell.exe——那个会闪黑窗）
      怎么查：PowerShell 里跑 (Get-ScheduledTask -TaskName 'DSH-Pal-Remote-Access').Actions
      期望：Execute 是 C:\\WINDOWS\\System32\\wscript.exe
- [ ] **重启后真的能自动恢复**（这条最容易被跳过，但最重要）
      怎么验：重启电脑 → 登录 → 打开 DSH → 手机连上，全程不用做别的
      如果这时候手机连不上，说明自启没装好

> **一个必须知道的事**：**DSH 本体重启后不会自己启动**（它是桌面程序）。
> 所以正常的开机流程是：**开机 → 手动打开 DSH → 手机自动连上**。
> 如果你希望 DSH 也自动开，告诉 AI，它会把 DSH 放进启动文件夹
> （代价是每次开机都会弹出 DSH 窗口）。

### ⚠️ 单独说一件事：这个插件正在「消失」，但我们已经帮你留了后路

**你不需要做什么，但应该知道发生了什么。**

#### 发生了什么

本 App 靠一个第三方插件（`@linxin666/dsh-remote-web-ui`）工作。
**它的作者已经放弃它了**，原文是：

> *"Browser-based remote control has been replaced by the native phone app, and this
> package no longer provides remote access capabilities."*

意思是：作者以后不管这插件了，而且新版会删掉「用浏览器远程控制电脑」这个能力 ——
**而这正是本 App 唯一依赖的能力。**

| 会怎样 | 什么时候 |
|---|---|
| 作者从 npm 下架这个包 | 可能随时 |
| 新版删掉 App 需要的接口 | 已经声明会做 |
| 你以后重装电脑，装不上 | 上面两件事发生后 |

#### 我们做了什么

**把插件完整复制了一份，放进本项目里**（`third_party/dsh-remote-web-ui/`），
并让你的 DSH 直接用它，而不是从网上下载。

翻译成人话：**插件不再"从网上拿"，而是"从你本地拿"。
就算原作者把网上那份删了，你这份还在，照样能用。**

#### 你怎么确认自己受保护了

跑一下这条命令（在项目目录里）：

```powershell
node tools/deploy-status.mjs
```

看输出里有没有这一行：

```
plugin: 已固化到本地（上游删包也不影响）
```

**有 → 你已经受保护，什么都不用做。**
**没有（显示"未固化"）→ 让 AI 跑 `node tools/vendor-plugin.mjs` 补上。**

#### 如果以后要重装

**不要再从网上下载了。** 用本项目自带的：

```powershell
node tools/vendor-plugin.mjs
```

它会自动从项目里的副本装好。详细说明见 [插件本地固化指南](PLUGIN-VENDOR-GUIDE.md)。

#### 一句话记住

**这个 App 的"零件"已经存进项目里了。
以后就算原厂倒闭，你照样能组装。**

## 五、功能怎么用：设置里那些入口分别是干嘛的

进 App 的「设置」页，从上往下的顺序：

| 入口 | 里面是什么 / 什么时候用 |
|---|---|
| **连接管理** | 「当前连接」+「切换连接方式」。**换通道就在这**：能看到所有已保存的入口、点一下切换、长按或点「删除」移除。下面还有「内置通道（Tailscale / WireGuard）」「添加其他连接」 |
| **连接帮助** | 按通道分方案写的配置教程。配不上时先看这里 |
| **悬浮助手** | 鲸鱼娘浮窗：「显示悬浮助手」总开关、显示标题、贴边自动收、大小样式 |
| **外观** | 跟随 DSH 背景 / 深浅色预设 / 自定义调色盘（滑动预览后点“应用配色”）、预测性返回、侧栏交互增强、网页布局；[配色步骤](appearance-and-diagnostics.md#浅色预设与自定义调色盘) |
| **通知与后台** | 「通知栏进度」「后台保持连接」「审批时震动」「结束后立刻收起」，以及灵动岛开关 |
| **缓存与加载** | 网页资源复用（省流量）、「对话本地缓存」（断网看历史，默认关） |
| **支持与诊断** | 日志记录、导出日志。**遇到问题先来这导出日志给 AI** |
| **关于** | 版本号、开源许可、项目链接 |
| **更新与公告** | 检查新版本、下载安装 |

### 几个容易找不到的东西

| 你想做的事 | 在哪 |
|---|---|
| 换一条连接通道 | 设置 → 连接管理 →「切换连接方式」里点那条 |
| 删掉某条连接 | 设置 → 连接管理 → 那条记录右边的「删除」，或长按那一行 |
| 让 App 启动就自动连 | 设置 → 连接管理 →「启动时自动连接」。关掉的话每次开 App 会先让你选入口 |
| Tailscale 登录 | 设置 → 连接管理 → 内置通道（Tailscale / WireGuard）→「登录 / 重新打开授权页」。**会跳出 App 到浏览器**（授权页域名是 `tailscale.com`，认准这个域名再输账号） |
| 断网时看历史 | 先在「缓存与加载」打开「对话本地缓存」，断网后从主界面进「离线看历史」 |
| 通道被自动切走了 | 那是在救你（原通道连续两次探测不通）。弹提示时点「继续用当前通道」可以留在原通道 |

### 电脑端 DSH 里多了一个「连接通道总览」（2026-11-06 新增）

> ⚠️ 这是**电脑上 DSH 的设置页**，不是手机 App 的设置页。两个不是一回事：
> 手机 App 决定「手机从哪条路连过来」，电脑 DSH 这边的面板决定「这台电脑开了哪几条路」。
>
> **设置左侧导航里只会多出这一个入口**（早先分成了「公网入口」和「连接通道总览」两个，
> 已合并）。所有通道状态、隧道切换、直连开关都在这一页里。

重启 DSH 后，DSH 设置里会多一个「连接通道总览」区块：

| 你会看到 | 含义 |
|---|---|
| ● 国内 frp 隧道 / Cloudflare 快速隧道 | 当前走哪条；不是当前的那条后面有「切到这条」按钮，点了会预检再切 |
| ● IPv6 直连 · **绿色 = 外面真的连进来过** | **黄色「外部未验证」= 本机绑上了，但还没证明外面能连**。校园网/蜂窝网络常阻断入站，这时绿不了 |
| ● Wi-Fi 直连 | 同一 Wi-Fi 下最快，不耗隧道额度；判定同上 |
| ● 组网通道（Tailscale / WireGuard） | 显示**登录账号**（如 `xxx@github`）和**通不通**：Tailscale 在线 = 正常；装了没登录/没隧道 = 没准备好 |
| 底部：本机公网 IPv6 / 网关 | 网卡上到底有没有公网 IPv6、remote-access 网关在不在跑 |
| 插件版本 + 检查更新 | 有新版本会列更新内容；点「立即更新」两步确认后更新。**有未提交改动时会拒绝更新**，不会覆盖你的代码 |

**怎么才能变绿**：用手机通过这条入口连一次（扫码配对或正常连上），网关记下「有外部请求」，
面板才给绿色。证据超过 7 天没更新会退回"未验证"。

**`fe80::` 这类地址不会出现**：链路本地/内网地址不是公网可达的，面板会明确写「已忽略 N 个非公网地址」，
绝不会把它当链接给你。

**每条通道后面都有「怎么办」**：哪条显示黄色/灰色，就点它后面的「怎么办」，展开的是**这一条**的排查步骤
（不共用一个按钮）。例如 IPv6 那位会依次告诉你：先用手机蜂窝数据自测 → 路由器后台怎么放行端口 →
是校园网/运营商阻断的话就换通道。正常通道不显示这个按钮。

**每条通道后面还有一个「配置说明」**：这是从零装到能用的安装流程（不用去翻文档）。
国内 frp 会告诉你注册实名 → 建隧道 → 保存密钥 → 生成配置 → 启动网关 → 出二维码；
IPv6 会告诉你两端怎么确认、命令怎么跑、路由器放行哪一步。展开区末尾有「打开完整文档 ↗」，
指向仓库里的 `docs/connections.md`。**「配置说明」和「怎么办」是两回事**：前者是安装，后者是排障。

**「国内 frp 隧道」名字后面有个「每天签到领流量」小标签**：SakuraFrp 的免费流量要每天签到领取，
不签到可能就没有可用额度、隧道会连不上。点这个标签直接打开官方用户中心（`natfrp.com/user/`）。
一次性给多少、能用多久，**以签到页上显示的为准**——官方公开文档没写死这些数字，我们也就不瞎写。

**「自定义 HTTPS 链接」这条给有自己的域名的人用**：如果你已经有能解析到这台电脑的域名、
并且能拿到受信任的证书（Let's Encrypt 够用），就不用注册 Sakura —— 在这一条后面的输入框里
填 `https://你的域名`，点保存即可。保存后它会自动把该域名登记进插件白名单（首次配对必需）。

- 常见做法：路由器/群晖上的 nginx、caddy 反代到这台电脑的网关端口（默认 18772）；
  或者用 Cloudflare Named 隧道绑自己的域名（地址固定，不会像 Quick 模式那样变）。
- **反代必须透传原始 Host 头**（nginx：`proxy_set_header Host $host;`），改写了会被白名单挡成 403。
- 只收 `https://` 加域名：`http://`、IP 地址、`localhost` 都会被拒绝；自签证书 App 不信任。
- 想撤掉就点「清除」，会回到原来 remote-access 配置的地址。
- 这条后面也有「配置说明」，点开是完整步骤（含 caddy 两行示例）。

状态来自网关每 5 秒写一次的实测结果（超过 20 秒没更新就判定网关没在跑），不是猜的。
直连开关写的是 remote-access 配置，网关 5 秒内热生效，**不用重启 DSH**。

**这条面板要重启一次 DSH 才会出现**（插件代码更新了）。

### 有新版会自己弹出来（不会让你不知情）

不用你自己去设置里点「检查更新」。插件在打开 DSH 时自动查一次，之后每 10 分钟查一次：

- 有新版本 → 屏幕中间弹出一张卡片（覆盖在对话之上），列出**这版改了什么**
- 两个按钮：**「立即更新」**（拉取最新代码）或者 **「稍后」**（这次不更）
- 点「稍后」只压住**这个版本**；下次发新版还会再弹，不会永久静默
- 更新成功后提示「重启 DSH 后生效」；如果插件目录有你没提交的代码，会**拒绝更新并说明原因**，不会覆盖

> 为什么要有这个：设置页里的按钮要靠人主动去点，绝大多数用户不会点 —— 结果就是一直用旧版。
> 所以改成主动提醒，但更新动作永远由你决定。

## 六、常见「以为是坏了，其实是没配」

| 现象 | 真实原因 | 怎么办 |
|---|---|---|
| 手机连不上，但电脑上看着一切正常 | 电脑的 DSH 只监听 `127.0.0.1`，手机要用网关地址 | 用远程访问面板给的二维码/地址，别自己填电脑 IP |
| 扫码后一直转圈 | 插件首屏资源约 8.7 MB，首次加载慢 | 等一会；第二次会走缓存变快 |
| 提示「需要配对」但 VPN 明明连着 | VPN 解决「网络通」，配对是另一层 | 重新扫一次码配对 |
| 切到后台一会儿就断，回来要重连 | 系统把 App 杀了（国产 ROM 省电策略） | 系统设置里把 DSH Pal 设为「不限制」 |
| 通知栏没有任务进度 | 通知权限没给（Android 13+ 要授权） | 系统设置授权；App 里有「通知能力检测」能看实际状态 |
| Tailscale 登录点了没反应 / 跳出浏览器 | 正常：授权在浏览器完成 | 在浏览器登录完，切回 App |
| 登录了 Tailscale 还要扫码 | 没装「登录后自动配对」插件，或那台手机不在同一 tailnet | 装上插件就不用扫了；不装就每次扫一次 |
| 正用着突然被切到另一条通道 | 通道自动选路的保命切换（会先弹提示倒计时 15 秒） | 点「继续用当前通道」保留；想彻底关在「通道自动选路」里关 |
| **重开 App 时一直转圈或白屏** | 上次用的那条连接已经失效了（以前 VPN 的网关、换过 IP 的局域网入口） | **不用管，App 会自己处理**：启动时先探一次，连不上就直接带你去「设备与连接」页，顶部会写清是哪条地址、为什么连不上。想再用那条就点「重试这条」；不想用就点「先不用这条」，然后在下面列表里点一条能用的 —— **那条坏连接不会被删** |

## 七、出了问题怎么给我（AI）反馈

导出日志比描述现象有用得多：

1. App → 设置 → 支持与诊断 → 日志记录（确认是开的）
2. App → 设置 → 支持与诊断 → 「导出日志」
3. 把导出的文件给我

**发给别人（比如提 GitHub Issue）之前先脱敏**：日志里可能有你的域名、内网 IP、设备名。
让我先看一眼，或者用 `node tools/deploy-status.mjs --share` 生成脱敏版。

## 八、AI 该怎么用这份清单（给 AI 的部分，用户可跳过）

> 用户前面看到的是他的版本，这一段是给你的执行要求。

1. **开始配之前**：把第一、二、三节的核心内容贴到对话里（不是只给路径），
   特别要**明确列出「哪些必须他本人做」**，让他提前准备好。
2. **配的过程中**：每完成一项，对照第四节的表说「已打勾 N 项，还差哪些」。
3. **配完之后**：把第四节整张核对表贴出来，让他逐条确认；打不了勾的**如实说没做完**。
4. **任何时候他说「我怎么感觉哪里不对」**：先回到这份清单对一遍，而不是先怀疑代码。

> 这份文件在 `docs/用户核对清单.md`。改功能/加通道/改默认值时，**同一次提交内**更新它（R-04）。
