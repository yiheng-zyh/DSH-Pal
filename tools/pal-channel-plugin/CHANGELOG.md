# dsh-pal-channel 更新记录

> 面板里的「更新公告」就来自这个文件：`lib/update.js` 读公开仓里的这份 CHANGELOG，
> 取**最新版本号对应的段落**展示。发版时在这里加一段，用户就能看到改了什么。
>
> **插件与 App 是两套独立编号**：App 用 `0.1.x`（`v0.1.1` 那种 Release tag），
> 插件从 `0.2.0` 起算。不要混用 —— 混用会让插件永远误报「有新版本」。

## 0.2.0 - 2026-11-07

从「一个只能切通道的开关」升级为「连接通道管理面板」。

### 新增

- **连接通道总览**：在 DSH 设置里一次看清所有通道 —— 公网隧道（国内 frp / Cloudflare）、
  IPv6 直连、Wi-Fi 直连、组网通道各自处于什么状态（当前使用 / 已开启 / 可切换 /
  未配置 / 已开启但未监听）。状态来自网关实测的 `state.json`（含 20 秒新鲜度校验），不是猜的。
- **直连入口开关**：IPv6 / Wi-Fi 直连可在面板里直接开关，写 remote-access 配置，
  网关 5 秒内热生效，不用重启 DSH。
- **自定义 HTTPS 链接**：有自己的域名/反代就不必走 Sakura，面板里填地址保存即用，
  自动登记 trustedHosts；只收 https 域名（http / IP / 自签一律拒绝），清除后回到原地址。
- **每条通道两个按钮，用途分开**：
  - 「配置说明」= 从零装到能用的安装步骤（正常状态下也能看）
  - 「怎么办」= 针对**这一条**的故障排查步骤（正常通道不显示）
- **组网通道显示真实账号与通断**：电脑侧读 Tailscale 登录账号（如 `yiheng-zyh@github`）、
  BackendState、在线状态，以及 WireGuard 有没有运行中的隧道。
- **外部可达性不再撒谎**：直连的绿色不再只看「已监听」。只有网关记录到「来自非本机地址的
  请求」才给绿色，否则黄色「外部未验证」并说明校园网/蜂窝常阻断入站。证据超 7 天退回未验证。
- **国内 frp 通道加「每天签到领流量」提醒**：SakuraFrp 免费流量要每天签到，不签到隧道会
  突然连不上（容易被误判成软件坏了）。额度与有效期不写死，只在签到页动态显示。
- **插件更新系统**（见下方「更新系统的设计与修复」）：显示版本、检查更新、更新公告、
  一键更新，以及**主动弹出**的更新提醒。

### 修复

- **更新检查误报「有新版本」**：把 GitHub Release 的 tag（那是 App 的 `v0.1.1`）当成了插件
  版本，与插件 `0.1.0` 混比 → 插件永远显示可更新，点完更新版本号不动。
  现在版本只读插件自己的 `package.json`。
- **点「立即更新」弹红字「没有配置远程地址」**：本机是 `link:` 指向私有开发区，那个库
  故意不配 remote（只出不进），所以必然命中。现在按 `local-ahead` / `local-behind` /
  `no-remote` 三种结论如实回报，不再把正常装法当故障。
- **版本比较按 `-` 切分导致带前缀版本判错**：`pal-plugin-0.1.10` 会被判成比 `0.1.9` 更旧。
  改为「找数字串」解析。
- **更新检查要等满 6 秒超时**：原来顺序降级（jsDelivr 超时才下一个），jsDelivr 在本机不通。
  改为三个镜像**并发**读、先回者胜，其余立即取消。实测 7.2s → 0.6s。
- 版本比较把预发布版本（`0.1.0-alpha.7`）判成与正式版（`0.1.0`）相同的问题。
- 通道体检的 IPv6 地址判据与网关不同源，会把 Teredo / WSL 等虚拟接口算成可用地址。
- `fe80::` 这类链路本地/ULA 地址不会再被当成可用链接（网关与面板各校验一次）。
- **切换通道不再杀另一条隧道**：原来切换时会停掉另一套客户端，文案却写「已停止」。
  现在只改公布地址，如实描述 `kept` / `started`。

## 0.1.0 - 2026-11-05

### 新增

- 在 DSH 界面里一键切换公网入口：国内 frp ⇄ Cloudflare 隧道。
- 切换前预检目标入口，验不过就拒绝切换，避免生成连不上的二维码。
- 切换时同步启停另一套隧道客户端，避免两条隧道同时占着出口。
- 写接口只允许本机桌面调用，远程配对设备一律拒绝。
